## 1. Contract Layer Entry Point

All blockchain interaction goes through **[`scripts/chain.js`](scripts/chain.js)**. Import it once in your Express app:

```javascript
const chain = require('./scripts/chain');
```

Never call `ethers` or the ABI directly from the backend — use `chain.*` wrappers only. If a function you need is missing, ask Srujan to add it to `chain.js`.

**Roles file:** `chain.js` reads `.env.roles.json` (generated by `npm run setup:roles`). Do not add any private key to the backend source. Keys live only in `.env` and `.env.roles.json` (both gitignored).

## 2. LandRegistry — Function Signatures & Arg Order

### `createClaim`
```
Solidity:  createClaim(address claimant, bytes32 ownerHash, bytes32 evidenceHash, int32 latE6, int32 lonE6)
chain.js:  chain.createClaim({ claimant, ownerHash, evidenceHash, lat, lon }, signerRole = 'REGISTRAR')
```
- `claimant`: the registered owner's Ethereum address (backend-assigned, not self-reported).
- `ownerHash`: `sha256(nationalID + salt)` — hash client-side before sending.
- `evidenceHash`: `sha256(photos + GeoJSON + witnesses)`.
- `lat` / `lon`: decimal degrees (e.g. `12.971598`, `77.594562`). `chain.js` converts to `int32 latE6 = Math.round(lat * 1e6)`. **Negative values are valid** — southern/western coordinates are supported.
- Returns: `{ txHash, blockNumber, claimId }`.

### `attest`
```
Solidity:  attest(uint256 claimId)   ← role is read from roles[msg.sender] on-chain
chain.js:  chain.attest(claimId, signerRole = 'NEIGHBOR1')
```
- `signerRole` is which wallet signs — it does **not** set the weight. The weight is set when the admin calls `setRole(addr, roleEnum)`.
- Valid signer roles in `.env.roles.json`: `NEIGHBOR1`, `NEIGHBOR2`, `NEIGHBOR3`, `LEADER1`, `NGO1`.
- Returns: `{ txHash, newScore, newStatus }`.

### `dispute`
```
Solidity:  dispute(uint256 claimId)   ← only registrar or arbiter
chain.js:  chain.dispute(claimId, signerRole = 'ARBITER')
```
- **Not publicly callable.** Caller must be `registrar` or `arbiter` on-chain.
- Returns: `{ txHash, status: 'Disputed' }`.

### `resolveDispute`
```
Solidity:  resolveDispute(uint256 claimId, bool restore)
chain.js:  chain.resolveDispute(claimId, restore, signerRole = 'ARBITER')
```
- `restore = true` → status returns to `Verified` (only if score ≥ 5 still holds); `restore = false` → status → `Pending`, score reset, round bumped.
- Returns: `{ txHash, restored, newStatus, round }`.

### Views

| chain.js call | Returns |
|---|---|
| `chain.statusOf(claimId)` | `{ statusCode: 0/1/2, status: 'Pending'/'Verified'/'Disputed' }` |
| `chain.claimantOf(claimId)` | `address` string |
| `chain.getClaim(claimId)` | `{ claimId, claimant, ownerHash, evidenceHash, lat, lon, score, round, statusCode, status, createdAt }` |

**`getClaim` return tuple positional layout (raw contract):**

| Index | Field | Type |
|---|---|---|
| `[0]` | claimant | address |
| `[1]` | ownerHash | bytes32 |
| `[2]` | evidenceHash | bytes32 |
| `[3]` | latE6 | int32 |
| `[4]` | lonE6 | int32 |
| `[5]` | score | uint32 |
| `[6]` | round | uint32 |
| `[7]` | status (enum) | uint8 |
| `[8]` | createdAt | uint256 (unix seconds) |

## 3. ReliefFund — Function Signatures & Arg Order

### `createRelief`
```
Solidity:  createRelief(bytes32 zoneHash, uint256 maxPerClaim, uint64 expiresAt) payable
chain.js:  chain.createRelief({ zoneHash, maxPerClaimMST, expiresAt, budgetMST }, signerRole = 'ADMIN')
```
- `budgetMST` is sent as `msg.value` — the contract holds native MST.
- `expiresAt`: unix timestamp. Budget can be swept after this.
- Returns: `{ reliefId, txHash }`.

### `assess`
```
Solidity:  assess(uint256 claimId, uint256 reliefId, uint8 damageLevel, bytes32 damageEvidenceHash)
chain.js:  chain.assessDamage({ claimId, reliefId, damageLevel, damageEvidenceHash }, signerRole = 'ASSESSOR')
```
- `damageLevel`: `1–4`.
- Only callable by addresses with `isAssessor === true`.
- Returns: `{ txHash, status: 'Assessed' }`.

### `approvePayout`
```
Solidity:  approvePayout(uint256 claimId, uint256 reliefId, uint256 amount, address payable beneficiary)
chain.js:  chain.approvePayout({ claimId, reliefId, amountMST, beneficiary }, officerRole = 'OFFICER1')
```
- Must be called **twice** with two **different** officer wallets, matching `amount` and `beneficiary`.
- `beneficiary` must equal `landRegistry.claimantOf(claimId)` — checked on-chain.
- Returns: `{ txHash }`.

### `release`
```
Solidity:  release(uint256 claimId, uint256 reliefId)   ← permissionless, no modifier
chain.js:  chain.releasePayout({ claimId, reliefId }, signerRole = 'ADMIN')
```
- **Any address can call this.** The function re-checks `Verified` status and dual approvals at execution.
- Returns: `{ txHash, status: 'Paid' }`.

### Views

**`getPayout(claimId, reliefId)` return tuple:**

| Index | Field | Type | chain.js key |
|---|---|---|---|
| `[0]` | status (enum) | uint8 | `statusCode` / `status` |
| `[1]` | damageLevel | uint8 | `damageLevel` |
| `[2]` | damageEvidenceHash | bytes32 | `damageEvidenceHash` |
| `[3]` | amount | uint256 (wei) | `amountMST` (formatted ETH) |
| `[4]` | beneficiary | address | `beneficiary` |
| `[5]` | officer1 | address | `officer1` |
| `[6]` | officer2 | address | `officer2` |
| `[7]` | releasedAt | uint256 (unix seconds) | `releasedAt` (ISO string or null) |

**`getRelief(reliefId)` return tuple:**

| Index | Field | Type | chain.js key |
|---|---|---|---|
| `[0]` | zoneHash | bytes32 | `zoneHash` |
| `[1]` | budget | uint256 (wei) | `budgetMST` (formatted ETH) |
| `[2]` | committed | uint256 (wei) | `committedMST` |
| `[3]` | paid | uint256 (wei) | `paidMST` |
| `[4]` | maxPerClaim | uint256 (wei) | `maxPerClaimMST` |
| `[5]` | expiresAt | uint64 | `expiresAt` (raw unix seconds) |
| `[6]` | active | bool | `active` |

## 4. Correct Event Names & Argument Order

Use **exactly** these names when parsing logs. Do not invent variations.

### LandRegistry Events

```
ClaimCreated(uint256 indexed claimId, address indexed claimant, bytes32 indexed ownerHash, bytes32 evidenceHash, int32 latE6, int32 lonE6)

ClaimAttested(uint256 indexed claimId, address indexed attester, Role role, uint32 newScore, ClaimStatus newStatus)

ClaimDisputed(uint256 indexed claimId, address indexed reporter)

DisputeResolved(uint256 indexed claimId, ClaimStatus newStatus, uint32 round)
```

### ReliefFund Events

```
ReliefCreated(uint256 indexed reliefId, bytes32 indexed zoneHash, uint256 budget, uint256 maxPerClaim, uint64 expiresAt)
   ← no admin arg

PayoutReleased(uint256 indexed claimId, uint256 indexed reliefId, uint256 amount, address indexed beneficiary)
   ← no txRef arg; amount comes BEFORE beneficiary

ClaimAssessed(uint256 indexed claimId, uint256 indexed reliefId, uint8 damageLevel, bytes32 evidenceHash)

PayoutApproved(uint256 indexed claimId, uint256 indexed reliefId, uint256 amount, address beneficiary, address officer)

ApprovalsReset(uint256 indexed claimId, uint256 indexed reliefId)
```

## 5. Role Numbers (for `setRole`)

```
Role.None     = 0   (default, cannot attest)
Role.Neighbor = 1   (weight +1)
Role.Leader   = 2   (weight +3)
Role.NGO      = 3   (weight +3)
```

Call: `landRegistry.setRole(address, roleNumber)` — only admin can call this.  
Registrar and Arbiter are **separate slots**, set via `setRegistrar(addr)` and `setArbiter(addr)`. There is no `Role.Registrar` enum value.

## 8. Coordinate Handling

- Contract stores `int32 latE6` and `int32 lonE6` (micro-degrees, signed).
- `chain.js` converts both ways automatically: `lat → Math.round(lat * 1e6)` on write; `res[3] / 1e6` on read.
- **Do not apply `>>> 0` or any unsigned cast to coordinates** — southern hemisphere latitudes and western longitudes are negative, and the contract uses `int32`, not `uint32`.
